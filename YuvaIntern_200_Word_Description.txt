This Week 4 project demonstrates device integration and interoperability testing through a software-based IoT Smart Home Automation scenario. The system contains two sensor devices, two actuator devices, a communication gateway/broker, and a monitoring logger. The temperature sensor publishes a numeric temperature value in degrees Celsius to a common topic. The motion sensor publishes a Boolean motion status to a separate topic. The simulated broker routes messages to the correct device logic using topic-based communication.

The integration rules are simple and testable. When the temperature is 28°C or higher, the smart fan receives an ON command; below 28°C, it receives an OFF command. When motion is detected, the smart light receives an ON command; when no motion is detected, it receives an OFF command. The Python simulation tests normal sensor readings, actuator command execution, and invalid data formats. It checks that temperature values are numeric and use the expected unit, and that motion values are Boolean. Invalid payloads are rejected and recorded instead of being silently accepted.

The project includes an architecture diagram, Python source code, a test log format, a test summary, and a technical report. The report explains device roles, message topics, data formats, integration steps, test cases, expected behavior, identified interoperability risks, troubleshooting actions, and possible improvements such as authentication, encryption, message timestamps, retry handling, and real-device validation.

The supplied results are generated by a local software simulation. No physical sensors, actuators, Wi-Fi network, or external MQTT broker were connected. This distinction is maintained so that the evidence accurately represents the work performed. The project shows how heterogeneous IoT devices can be organized around a shared communication model and how compatibility can be checked systematically before deployment.
